# Release v0.3.0-rc.1

> **Release Candidate** — 2026-07-28
> SemVer-Präfix: `rc.1` (Release Candidate 1)

## Zusammenfassung

Numra 0.3.0-rc.1 ist der erste Release Candidate der kumulativen
Normalisierungsrunde. Er führt die DeepSeek-Live-Aktivierung mit Thinking-Modus,
das V2-Wissensmodell mit Compound-Struktur, und signifikante UX/Accessibility-
Verbesserungen ein — bei strikter Einhaltung des Determinismus-vor-LLM-Prinzips.

## Hauptänderungen

### DeepSeek-Live-Aktivierung (PR B)

- **v2-Verträge:** `analysis-report-v2`, `analysis-follow-up-v2`,
  `numra-report-de-v2`, `numra-follow-up-de-v2`. V1 bleibt als Lese-Struktur.
- **Thinking-Modus:** `reasoning_effort=high`, `thinking.type=enabled`.
  Sampling-Parameter (`temperature`/`top_p`) werden nicht mehr gesendet
  (provider-managed). Provenance trägt `temperature=null`, `top_p=null`.
- **Provider-Retry:** Transiente Fehler (429/502/503/504/Netz/Timeout) mit
  Backoff+Jitter; harte Fehler (400/401/403) fail-closed.
- **Circuit-Breaker:** Öffnet nach 5 Fehlern für 60s.
- **reasoning_content-Hygiene:** Thinking-Trace erscheint nie in
  ProviderResult/Bericht/Export/Logs/API-Antwort.
- **Env-Variablen:** `DEEPSEEK_*` als bevorzugt, `NUMRA_DEEPSEEK_*` als
  Fallback (Deprecated-Warning ohne Secret).
- **Prompts aus Dateien:** `prompts/` mit 10 Systemprinzipien.
- **Live-Smoke:** Opt-in via `NUMRA_RUN_LIVE_DEEPSEEK_TESTS`.

### Knowledge de-v2 (PR C)

- **Compound-Struktur:** `CompoundNotation` (raw_value/reduced_value/
  compound_notation) statt `number:int` für Compounds.
- **41 Einträge:** 10 Single-Digits, 3 Master Numbers, 24 Compounds,
  4 Karmaschulden.
- **Kontextsensitiver Resolver:** Trennung von `number:4` (single) vs.
  `compound:13/4` vs `master:22`.
- **rules.py:** Nicht-wertende Beziehungsregeln (Reinforcement, Tension,
  Core-vs-Active, Maturity-Alignment).
- **validate_knowledge.py:** Neuer CI-Check für V1+V2.

### UX/Accessibility (PR D)

- **AbortController + Abbrechen-Button** für alle API-Aufrufe.
- **Skip-to-Content-Link** für Screenreader/Tastatur.
- **Server-Quota-Display** statt irreführendem localStorage-Quota.
- **Insight→Next-Step-Brücke:** Notizen pro Report-Abschnitt (rein lokal).
- **PWA-Update-Toast:** Auto-Focus auf Update-Button.

## Neue Umgebungsvariablen

| Variable                     | Standard                   | Beschreibung                                              |
| ---------------------------- | -------------------------- | --------------------------------------------------------- |
| `DEEPSEEK_API_KEY`           | (leer)                     | DeepSeek API-Schlüssel (ersetzt `NUMRA_DEEPSEEK_API_KEY`) |
| `DEEPSEEK_BASE_URL`          | `https://api.deepseek.com` | DeepSeek Basis-URL                                        |
| `DEEPSEEK_MODEL`             | `deepseek-v4-pro`          | DeepSeek Modell                                           |
| `DEEPSEEK_THINKING_ENABLED`  | `true`                     | Thinking-Modus aktivieren                                 |
| `DEEPSEEK_REASONING_EFFORT`  | `high`                     | Reasoning-Aufwand                                         |
| `DEEPSEEK_MAX_OUTPUT_TOKENS` | `8192`                     | Maximale Ausgabetokens                                    |
| `DEEPSEEK_MAX_RETRIES`       | `3`                        | Maximale Provider-Retries                                 |

`NUMRA_DEEPSEEK_*`-Variablen bleiben als Fallback gültig (Deprecated-Warning).

## Bekannte Einschränkungen

- Keine Tool-Calls im DeepSeek-Adapter (alle Aufrufe sind One-Shot).
- Live-Smoke-Test nur mit echtem API-Key ausführbar.
- Kein GitHub-Release/Tag bis zum Staging-Gate.
